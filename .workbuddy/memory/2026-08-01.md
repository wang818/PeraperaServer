# 2026-08-01

## Enhanced GET /api/v1/common/yt_audio with YouTube video metadata
- Added `_fetch_video_info(video_id, api_key)` helper in `app/api/v1/endpoints/common.py` that calls `youtube-v2.p.rapidapi.com/video/details?video_id=...` (async httpx, best-effort → returns None on failure/missing key). Uses `settings.RAPIDAPI_KEY`, NOT hardcoded key.
- `download_youtube_audio` now: fetches video info after quota check, prefers `video_info["title"]` for the COS filename, and returns `video_info` in the JSON response.
- `quota_service.get_video_duration_seconds` still uses yt-dlp for billing duration (unchanged).
- Added `from typing import Optional` import. Verified module imports cleanly.
- NOTE: `yt_video` endpoint was NOT changed (only yt_audio per request). Could mirror the same video-info fetch if desired.

## Added GET /api/v1/common/yt_info (standalone YouTube metadata endpoint)
- New `get_youtube_info` route in `app/api/v1/endpoints/common.py`: takes `url` query param, extracts video_id via `_extract_video_id`, calls `_fetch_video_info`, returns the raw RapidAPI JSON.
- Pure read, no download, no quota consumption. Per user request (10:18) → now REQUIRES LOGIN (`current_user: User = Depends(get_current_user)`), consistent with `yt_audio`.
- 500 if RAPIDAPI_KEY missing; 502 if metadata fetch fails. Reuses existing `_fetch_video_info` helper + `settings.RAPIDAPI_KEY`. Verified route registered at `/yt_info` with `get_current_user` in dependant tree.
